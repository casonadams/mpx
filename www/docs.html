mpx Documentation

An ultra-performant, zero-overhead terminal and stream multiplexer engineered in Rust for humans and autonomous AI coding agents.

100% Local & Zero Telemetry: Offline-by-design. Zero analytics, zero network calls, zero telemetry, and zero model training. Complete data sovereignty.

Getting Started

Running bare mpx automatically bootstraps a background daemon, opens your default shell in an interactive PTY, and launches the full-screen terminal interface:

# Start or attach to the default "main" session (just like tmux)
mpx

# Start or attach to a named session
mpx -s dev

TUI Keybindings & Navigation

Ctrl-b is the prefix (configurable, e.g. prefix = "C-a" in ~/.config/mpx/config.toml). Press it twice to send it to the program. When tmux has no precedent, bindings follow vim.

Mouse Mode

  • Left Click: Focus clicked pane immediately (no copy mode).
  • Left Drag: Select text from the press point; release copies it.
  • Scroll Up: Automatically enters copy mode and scrolls history upward.
  • Scroll Down: Scrolls downward toward live output.

Model Context Protocol (MCP) Server

mpx features a native stdio Model Context Protocol (MCP) server conforming to the 2024-11-05 standard. AI coding assistants like oh-my-pi, claude code, Cursor, and Windsurf can orchestrate terminal processes directly without scraping ANSI screen sequences.

Agent Configuration (.mcp.json)

{
  "mcpServers": {
    "mpx": {
      "command": "mpx",
      "args": ["mcp"]
    }
  }
}

Exposed MCP Tools (22)

  • mpx_run, mpx_split, mpx_new_window, mpx_list, mpx_status, mpx_kill, mpx_focus, mpx_sessions: processes, panes and sessions
  • mpx_read(name, tail, plain, since): incremental output reads returning {text, next}; mpx_screen(name): rendered screen
  • mpx_send, mpx_send_keys (tmux key names), mpx_paste (bracketed, optional submit)
  • mpx_wait(name, condition): exit, quiet output, regex match, or agent state, with timeout
  • mpx_pipe_write, mpx_pipe_read (consumer cursors, long-poll), mpx_pipe_create, mpx_pipe_list
  • mpx_agents, mpx_agent_launch, mpx_agent_prompt: list, start and prompt other agents; mpx_restore: recreate a session from its snapshot
  • Mutating tools accept an optional idempotency_key, so retries never act twice

Inter-Agent Virtual Pipes

Virtual pipes are sequenced message queues. Each message has a sequence number, named consumers keep daemon-side cursors, readers can long-poll before any writer exists, and messages and cursors persist across daemon restarts:

# Write messages (the pipe is created on first use)
mpx pipe write agent_bus '{"action": "test_complete", "code": 0}'

# Each consumer receives every message once; block up to 30s
mpx pipe read agent_bus --consumer reviewer --wait 30000

# Stream messages as they arrive
mpx pipe subscribe agent_bus

Session Restore

The daemon snapshots each session's layout as it changes. After a crash or reboot, the next start brings back the windows, splits and working directories, and agents resume their conversations through their harness. After a deliberate mpx kill-server, run mpx restore to bring the layout back.

CLI Command Reference

mpx                              # Start or attach to default session
mpx ls                           # List sessions (tmux ls)
mpx list-panes                   # List panes with ids (%N) and status
mpx run --pty -- htop            # Run interactive command in PTY
mpx split -h -d -- htop          # Split side by side without focus (tmux flags)
mpx logs --plain --tail 50 <name> # Rendered scrollback
mpx send-keys -t %1 C-c          # tmux key names
mpx paste -t %1 --submit "text"  # Bracketed paste + Enter
mpx wait <name> --state needs_input --timeout 60
mpx agents                       # Agent manager
mpx agents new claude --split    # Launch an agent with hooks installed
mpx kill-server                  # Stop the session daemon
mpx mcp                          # Launch stdio MCP server
