mpx Documentation

An ultra-performant, zero-overhead terminal and stream multiplexer engineered in Rust for humans and autonomous AI coding agents.

100% Local & Zero Telemetry: Offline-by-design. Zero analytics, zero network calls, zero telemetry, and zero model training. Complete data sovereignty.

Getting Started

Running bare mpx automatically bootstraps a background daemon, opens your default shell in an interactive PTY, and launches the full-screen terminal interface:

# Start or attach to the default "main" session (just like tmux)
mpx

# Start or attach to a named session
mpx -s dev

TUI Keybindings & Navigation

Ctrl-b is the prefix (configurable, e.g. prefix = "C-a" in ~/.config/mpx/config.toml). Press it twice to send it to the program. When tmux has no precedent, bindings follow vim.

Mouse Mode

  • Left Click: Focus clicked pane immediately (no copy mode).
  • Drag a Border: Resize the panes on either side of it.
  • Left Drag: Select text from the press point; release copies it.
  • Scroll Up: Automatically enters copy mode and scrolls history upward.
  • Scroll Down: Scrolls downward toward live output, leaving copy mode on reaching it when the wheel entered it.

Vi Copy / Visual Mode

Configuration (config.toml)

mpx reads configuration in TOML format at startup from the first discovered location:

  1. $MPX_CONFIG
  2. $XDG_CONFIG_HOME/mpx/config.toml
  3. %APPDATA%\mpx\config.toml (Windows)
  4. ~/.config/mpx/config.toml

A missing file loads safe defaults. Unknown keys are strictly rejected to surface typos immediately. Pass -f <FILE> or --config <FILE> before any command to supply an explicit path.

Sample config.toml

prefix = "C-b"          # tmux notation: C-a, C-Space, M-b ...
remain_on_exit = false  # keep panes on screen after their process exits
history_limit = 64      # exited, removed panes whose logs stay readable
tmux_compat = false     # export TMUX/TMUX_PANE + the tmux shim in every pane
allow_passthrough = true # allow terminal passthrough sequences (DCS tmux, OSC 4/10/11/12/52) from active pane
restore = true          # after a crash or reboot, recreate layout and resume agents
persist_pipes = true    # keep pipe messages and consumer cursors across restarts
which_key_delay_ms = 300  # delay before showing the shortcut HUD popup (0 = at once)

[style]
border_active = "bright-green"      # active border color or hex ("#3fb950")
border_inactive = "bright-black"    # inactive border color or hex ("#263345")
border_style = "single"             # "single", "rounded", "double", "ascii"
status_bg = "dark-green"            # status line background or hex ("#121820")
status_fg = "black"                 # status line foreground or hex ("#c5d1de")
dim_inactive = true                 # dim inactive panes when multiple are visible
dim_factor = 0.20                   # dim factor (0.20 = 20% reduction)
dim_content_bg = true               # dim explicit app backgrounds (diffs, selections)

# Optional template for active (focused) pane
[style.active]
fg = ""                             # default text color (empty for terminal default)
bg = ""                             # default background color

# Optional template for inactive (unfocused) panes
[style.inactive]
fg = "#4c566a"                      # default text color in inactive panes (e.g. muted slate/grey)
bg = "#242933"                      # optional surface background tint for inactive panes
color_mode = "desaturate"           # syntax color mode: "dim", "desaturate", "tint", or "none"
factor = 0.25                       # color transformation intensity (0.0 to 1.0)
dim_content_bg = true               # transform explicit app background colors in inactive panes

[agent]
idle_ms = 1500          # quiet period before a hook-less agent counts as idle
notify = true           # OSC 9 desktop notification when an off-screen agent needs input
mcp = true              # give agents mpx launches the mpx MCP tools (mpx_peers, mpx_agent_prompt, ...)

[bind]                  # custom prefix key bindings -> command line
"M-h" = "select-pane -L"
"g" = "launch-agent claude --split"

[bind_root]             # keys without the prefix; "" unbinds
"M-j" = "next-agent"
"r" = "command-prompt -I 'rename-window '"

# Define custom aider harness
[[harness]]
name = "aider"
detect = ["aider"]
command = ["aider"]
resume = []
session_id_args = []

# Define custom internal harness (multiple [[harness]] blocks supported)
[[harness]]
name = "myagent"
detect = ["myagent-bin"]
command = ["myagent", "--mode", "autonomous"]
resume = ["myagent", "--resume", "{id}"]
session_id_args = ["--session", "{id}"]

Applying & Reloading Configuration

  • TUI & Visual Settings (prefix, [style], [bind], which_key_delay_ms): Re-read automatically whenever attaching to a session. Detach with Prefix + d and re-attach with mpx to apply edits immediately.
  • Daemon Settings (remain_on_exit, restore, persist_pipes, tmux_compat, history_limit, [[harness]]): Read when the background daemon starts. Run mpx kill-server and then mpx (or mpx restore) to restart with new daemon settings.

Model Context Protocol (MCP) Server

mpx features a native stdio Model Context Protocol (MCP) server conforming to the 2024-11-05 standard. AI coding assistants like oh-my-pi, claude code, Cursor, and Windsurf can orchestrate terminal processes directly without scraping ANSI screen sequences.

Agent Configuration (.mcp.json)

{
  "mcpServers": {
    "mpx": {
      "command": "mpx",
      "args": ["mcp"]
    }
  }
}

Exposed MCP Tools (22)

  • mpx_run, mpx_split, mpx_new_window, mpx_list, mpx_status, mpx_kill, mpx_focus, mpx_sessions: processes, panes and sessions
  • mpx_read(name, tail, plain, since): incremental output reads returning {text, next}; mpx_screen(name): rendered screen
  • mpx_send, mpx_send_keys (tmux key names), mpx_paste (bracketed, optional submit)
  • mpx_wait(name, condition): exit, quiet output, regex match, or agent state, with timeout
  • mpx_pipe_write, mpx_pipe_read (consumer cursors, long-poll), mpx_pipe_create, mpx_pipe_list
  • mpx_agents, mpx_agent_launch, mpx_agent_prompt: list, start and prompt other agents (session:pane reaches another session); mpx_peers: other agents in your repository with their current task and recent edits; mpx_restore: recreate a session from its snapshot
  • Mutating tools accept an optional idempotency_key, so retries never act twice

Inter-Agent Virtual Pipes

Virtual pipes are sequenced message queues. Each message has a sequence number, named consumers keep daemon-side cursors, readers can long-poll before any writer exists, and messages and cursors persist across daemon restarts:

# Write messages (the pipe is created on first use)
mpx pipe write agent_bus '{"action": "test_complete", "code": 0}'

# Each consumer receives every message once; block up to 30s
mpx pipe read agent_bus --consumer reviewer --wait 30000

# Stream messages as they arrive
mpx pipe subscribe agent_bus

Session Restore

The daemon snapshots each session's layout as it changes. After a crash or reboot, the next start brings back the windows, splits and working directories, and agents resume their conversations through their harness. After a deliberate mpx kill-server, run mpx restore to bring the layout back.
